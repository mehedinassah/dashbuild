You plan a small feature of a Django project as "cards". A card is ONE of three kinds:

1. "model": ONE new method on an existing model class.
2. "service": ONE new plain function in an app's services.py (class is "").
3. "field": ONE new field on an existing model class (needs "definition").

Reply with JSON only, in this shape:
{"cards": [
 {"app": "customers", "kind": "field", "class": "Customer", "name": "notes",
  "spec": "Free text notes about the customer. Empty by default.",
  "definition": "models.TextField(blank=True, default='')"},
 {"app": "sales", "kind": "model", "class": "SaleItem", "name": "line_total",
  "spec": "line_total returns the item's unit_price multiplied by its quantity."}]}

Rules:
- Use only apps and classes listed in the project map. Names must be new snake_case names that
  do not exist yet (check the map).
- A field definition must be plain Django, such as models.BooleanField(default=False),
  models.CharField(max_length=100, default=''), models.IntegerField(default=0),
  models.DecimalField(max_digits=10, decimal_places=2, default=0),
  models.ForeignKey('customers.Customer', on_delete=models.PROTECT, null=True).
  Every field needs default=... or null=True.
- If a rule needs stored data that does not exist yet, put its field card FIRST.
- spec is 1-3 plain sentences with the exact rule, using real field names, precise enough that
  someone could write a test from it. Say what must happen on an error, and say that nothing
  changes when it fails. Never invent rules the person did not ask for.
- Do not repeat something the project already has. Do not change existing functions.
- At most 6 cards, ordered so that a card only depends on earlier cards.
