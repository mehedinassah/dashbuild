Tools: show_models() and write_tests(code). Make exactly one tool call per reply.

Rules for the test file:
- Start with: from django.test import TestCase  (and from decimal import Decimal if you use decimals).
- Import models from the app, for example: from sales.models import Product
- One class that extends TestCase, with 3 to 5 methods named test_...
- Create rows with Model.objects.create(...) using ONLY field names shown by show_models.
- Work out each expected value BY HAND and write it as a literal number, for example Decimal("30.00").
  Never compute the expected value with the code under test.
- Every test must check an exact value with assertEqual / assertTrue / assertFalse / assertRaises.
- Write 3 or 4 tests: a normal case, a zero/empty case, a second normal case with different numbers,
  and the BOUNDARY: if the rule compares with a number, test the value exactly at that number and one
  step on each side (for example stock 0 and stock 1 when the rule is stock > 0).
- Test ONLY what the rule says. Never invent errors, exceptions, messages or extra behaviour.
- Create EVERY required related row. A SaleItem needs a sale AND a product. Never create a row with a
  missing required field: that crashes the test before it checks anything.
- When the rule says something is saved, call obj.refresh_from_db() before checking the value, so the
  test reads what is really stored in the database.
- Do NOT write the feature itself. The tests must fail now because it does not exist yet.
